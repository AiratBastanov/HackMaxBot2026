# Типы событий и независимые закладки

27.09.2026. База изменения: `823d51852160c3d1bede1dd1f1abde2769c3ed1e`, после исправлений запуска/TLS/polling и настройки организатора. PUBLIC, порядок сообщений, конфигурация организатора, источники и презентации сохранены. Рабочие базы не открывались и не мигрировались; действующие процессы не останавливались.

## Причина и проверенное поведение

Выводы архивного `32127a0` подтвердились на текущем приложении. `Card.identity` — digest события/сеанса; прежний ключ закладки — `(actor, identity)`. `INSERT OR IGNORE` пропускал новый вариант того же события/периода, но обработчик сообщал об успехе. HTTP → worker → настоящая SQLite → симулированный MAX дали **1 → 1 → 2** записи: другой выбор не вставлен, первоначальная запись побайтно неизменна, другое одноимённое событие из отдельного поиска (снова результат № 1) вставлено. Это соответствует [семантике IGNORE](https://www.sqlite.org/lang_conflict.html); замена через REPLACE не используется. [UPSERT](https://www.sqlite.org/lang_upsert.html) также не нужен для создания новой закладки.

Перезапись, скрытие сохранённой строки, перенос выбора или удаление закладки очисткой сообщений не воспроизведены. Общий предел 50 — отдельное ограничение. Найдено расхождение нумерации второй страницы: видимые строки 6–10 имели кнопки 1–5; номера теперь совпадают. Сами callbacks и прежде ссылались на ID/поколение, а не на название или номер.

## Изменение

- Общий formatter добавляет один тип из сохранённых категорий: Концерт, Театр, Выставка, Экскурсия, Мастер-класс, Образовательное событие, Культурное событие. Конкретный тип приоритетнее общего; неизвестный — «Тип не указан». Raw title, категории источника, fingerprint и ID события не меняются. Суффикс остаётся целым при сокращении заголовка; полное название доступно в условиях.
- Новый UUID закладки независим от `Card.identity`; отдельный UUID поколения защищает удаление. `save_action` — ID исходной кнопки, не доставки callback. Plain INSERT, результат операции, погашение действий и переход фиксируются в одной worker-транзакции; сбой откатывает всё. Повтор кнопки не добавляет запись, свежая «Сохранить ещё раз» добавляет. Предыдущие записи никогда не заменяются.
- Пересечения времени допустимы; предупреждение сравнивает только известные выбранные интервалы в UTC. Соседние интервалы, неизвестная длительность и весь период выставки не считаются занятостью. Список по пять записей упорядочен по `saved_at DESC, identity`; контекст и двухкнопочное подтверждение различают варианты.
- Миграция v3 → v4 добавляет одно nullable-поле и индексы, без переписывания старых строк. Старые save-кнопки погашаются из-за изменившегося смысла; открытие/удаление legacy-записи сохраняет точную привязку. Повторный старт безопасен, несовпадение identity откатывает миграцию. Удаление данных и recovery охватывают новые поля без дополнительного реестра.
- Обновление каталога отдельно переоценивает каждый безопасно сопоставленный вариант, сохраняя исходный выбор. Для legacy допустима категория только из разрешённого текущего match. Недоступная запись показывает параметры запроса пользователя без раскрытия фактов источника. Истёкшая дата не переносится на новый сеанс.

## Контролируемое обновление

**Не выполнено в этой задаче.** Для настроенного PUBLIC polling из README: после завершения оператором текущего foreground-сеанса (Ctrl+C), в той же папке, с прежним Compose project, `.env.public`, секретами и CA. Нельзя использовать `down -v`, новый project или подменять исходный том резервной копией.

```powershell
$bookmarkCompose = @('--env-file', '.env.public', '-f', 'compose.polling.yaml')
if (Test-Path -LiteralPath compose.ca.override.yaml) {
    $bookmarkCompose += @('-f', 'compose.ca.override.yaml')
}
docker compose @bookmarkCompose stop
if ($LASTEXITCODE -ne 0) { throw 'Остановка не подтверждена' }
$bookmarkBotId = [regex]::Match((Get-Content -LiteralPath .env.public -Raw), '(?m)^MAX_EXPECTED_BOT_ID=(\d+)\s*$').Groups[1].Value
if (-not $bookmarkBotId) { throw 'Не найден ID своего бота в .env.public' }
$bookmarkBackup = 'runtime/backups/before-bookmarks-v4-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.sqlite'
docker compose @bookmarkCompose run --rm --no-deps app node dist/scripts/recovery.js backup live $bookmarkBotId runtime/public.sqlite $bookmarkBackup
if ($LASTEXITCODE -ne 0) { throw 'Backup не завершён; обновление остановлено' }
docker compose @bookmarkCompose up --build
```

Backup создаётся существующим образом **до** сборки/старта новой версии и остаётся в приватном томе. После успешного backup новый запуск транзакционно применит v4. Обычная команда `restart` без пересборки не применяет новый код. Если текущий способ запуска отличается от PUBLIC Compose-профиля README, сохраните его исходные project/путь базы/параметры; приведённые команды не переключают способ запуска автоматически. Старые backups не восстанавливают поверх действующей базы: [правила карантина](../RECOVERY_RUNBOOK.md).
