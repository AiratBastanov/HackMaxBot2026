## Воспроизведение и продолжение

На хосте нужны Node версии из package.json, установленные зависимости и curl с обычной TLS-проверкой; Docker runtime уже содержит curl. Кандидат собирается независимо от установки:

```powershell
npm.cmd run build
node dist/scripts/real-catalog.js multi-collect .cache/real-catalog/multi-city-20260928
```

Это **точная команда продолжения текущей кампании**: тот же ledger/cache/frontier, успешные ответы не скачиваются повторно, новая волна ≤30 минут. Выбранный город: добавить `city:spb`; источник: добавить `novat` либо несколько IDs. Чистый переразбор без сети:

```powershell
node dist/scripts/real-catalog.js multi-reparse .cache/real-catalog/multi-city-20260928
```

При реально завершившемся владельце lock: `node dist/scripts/real-catalog.js multi-recover .cache/real-catalog/multi-city-20260928`; команда проверяет отсутствие PID и дописывает незавершённую волну/ответы консервативно. Живого владельца не прерывает. Достижение общего предела запрещает новые fetch, но не offline parsing. Исходный private cache не публикуется; новая машина начинает собственную явно ограниченную съёмку, а не воспроизводит HTTP-наблюдения из выдуманных fixtures. Следующая независимая съёмка после истечения данных использует новое имя; это не способ сброса текущего лимита. Conditional GET не реализован: кеш — не revalidation.

Команда возвращает candidate path и SHA-256 канонического CandidateFile. Для текущего подготовленного кандидата:

```powershell
$env:ADMISSION_MODE = 'PUBLIC'
node dist/scripts/real-catalog.js activate .cache/real-catalog/multi-city-20260928/candidate-83664734f5fbb931cb19.json 83664734f5fbb931cb193a0574a4cf7d11762fd71fb30e1431ac5b2450b75fa2 runtime/max-test/multi-city-candidate
```

В репозитории уже установлены [active.json](../../catalog/real/active.json), snapshot `83664734f5fbb931cb19.json` и его review. Это не указатель работающего контейнера. Путь процесса — `/app/runtime/catalog/active.json`; первоначальная установка seed копирует bundle только при отсутствии pointer. Обновлённый образ сам по себе старый runtime pointer не заменяет.

Проверки локального комплекта: `node scripts/multi-city-checks.mjs typecheck`, затем `build`, `shared`, `matrix`, `journeys`; `container` проверяет финальную упаковку отдельно. Watchdog и прежний frozen matrix относятся к этой приёмке; запуск позже срока свежести закономерно не подтверждает сентябрьский каталог. [Sanitized пакет и hashes](../evidence/multi-city/sources.json), генератор `python scripts/package-multi-city.py`.

## Контролируемое обновление работающей установки — не выполнялось

Оператор сначала завершает текущий foreground polling через Ctrl+C. Для уже настроенной установки `cultural-plan-polling` сохраняются её project, `.env.public`, оба Compose-файла и том. Эти команды не выполнялись в данной задаче:

```powershell
Set-Location -LiteralPath C:\Users\BastaPC\Desktop\MaxBotHack
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Код не обновлён' }
$multiCompose = @('-p', 'cultural-plan-polling', '--env-file', '.env.public', '-f', 'compose.polling.yaml', '-f', 'compose.ca.override.yaml')
docker compose @multiCompose stop app
if ($LASTEXITCODE -ne 0) { throw 'Остановка не подтверждена' }
$multiBotId = [regex]::Match((Get-Content -LiteralPath .env.public -Raw), '(?m)^MAX_EXPECTED_BOT_ID=(\d+)\s*$').Groups[1].Value
if (-not $multiBotId) { throw 'Не найден ID своей установки' }
$multiBackup = 'runtime/backups/before-multi-city-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.sqlite'
docker compose @multiCompose run --rm --no-deps app node dist/scripts/recovery.js backup live $multiBotId runtime/public.sqlite $multiBackup
if ($LASTEXITCODE -ne 0) { throw 'Backup не завершён' }
docker compose @multiCompose build app
if ($LASTEXITCODE -ne 0) { throw 'Образ не собран' }
$multiPointer = Get-Content -LiteralPath catalog/real/active.json -Raw | ConvertFrom-Json
$multiSha = (Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path catalog/real $multiPointer.snapshot)).Hash.ToLowerInvariant()
docker compose @multiCompose run --rm --no-deps app node dist/scripts/real-catalog.js install-bundled $multiSha
if ($LASTEXITCODE -ne 0) { throw 'Установка каталога не прошла проверку; polling не запускался' }
docker compose @multiCompose up --no-build
```

`install-bundled` проверяет PUBLIC review, hashes, свежесть и коллизию versioned файлов, атомарно заменяет только catalog pointer; БД/закладки/cursor не открывает. SHA в команде вычисляется по точным байтам своего checkout, включая его окончания строк; семантические snapshot/policy hashes дополнительно проверяются независимо. Если комплект уже устарел, вместо install-bundled выполните **новую** ограниченную съёмку `docker compose @multiCompose run --rm --no-deps app node dist/scripts/real-catalog.js multi-refresh runtime/source-cache/refresh-01`; при необходимости продолжите с тем же путём. Запуск polling — только после успешной проверки свежего результата. Планировщик/фоновая служба не добавлены.

Применены записанные официальные ссылки: [Codex Prompting Guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide), [Model guidance](https://developers.openai.com/api/docs/guides/latest-model), [Rethinking skills and prompts](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra): сохранение текущей архитектуры и успешных контрактов, автономное завершение разрешённой задачи, целевые доказательства и чтение контекста по зависимости. Настройки модели не менялись.
