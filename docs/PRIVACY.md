# Данные пользователя

Бот хранит lossless MAX user/chat ID, состояние доступности личного диалога, выбранный город, даты/время, бюджет, состав посетителей, необязательный возраст детей в годах и до 50 личных закладок. Имена, телефоны, профиль и даты рождения для допуска не нужны; полные входящие MAX JSON/профили в БД не сохраняются. В SQLite попадает ограниченное нормализованное событие, необходимое для обработки.

Настройки служат подбору; закладки — повторному открытию выбранного события/сеанса без смены сохранённого состава. Сохранение не является покупкой, регистрацией или согласием на сообщения. Напоминаний, рассылок, групп и рекламных профилей нет. Источникам афиши пользовательские параметры не отправляются. MAX обрабатывает сообщения по своим условиям.

Каждый сохранённый вариант имеет отдельный ID и сохраняет исходный выбор. Точный повтор того же посещения с тем же составом не создаёт новую запись; прежние одинаковые копии остаются отдельно удаляемыми. Новые закладки содержат также необязательные категории источника и ID использованной кнопки сохранения для защиты от повторной доставки. Эти поля удаляются вместе с закладкой; отдельного реестра удалённых вариантов нет. «Удалить N» в списке и «Удалить закладку» в карточке с подтверждением удаляют только выбранную запись.

«О данных → Удалить мои данные» или `/delete_data` → подтверждение удаляет настройки, закладки, контакт, экранные ID и прежние персональные payload очереди в транзакции до отправки ответа. Для короткого подтверждения адресат и ID callback временно остаются в очереди со сроком 60 секунд; worker очищает их после отправки, отказа или истечения срока. Сбой доставки не отменяет удаления; запоздавшее завершение подтверждения не стирает новый диалог. История чата MAX и ранее созданные оператором резервные копии отдельно не стираются. Новое личное обращение создаёт новое состояние, прежние кнопки его не восстанавливают.

В рабочем процессе обработанные payload очищаются через 24 часа, служебные записи дедупликации — через 7 дней; истёкшие действия удаляются, неактивные состояния — через 30 дней. Контакты без состояния/закладок удаляются после 7 дней. Закладки хранятся до удаления пользователем. Очистка выполняется работающим worker; остановленная БД сама не очищается. Доступ к файлам и резервным копиям ограничивает оператор хоста. Секреты монтируются отдельными read-only файлами. Диагностика отказов содержит метод, категорию, разрешённый код провайдера, длины/структуру payload и техническую ссылку операции; тексты, токены, user ID и произвольное тело ошибки в лог не попадают.

Оператор, контакты для обращений, место размещения и порядок очистки резервных копий пока не определены. Эти поля должны быть заполнены до постоянного размещения; локальный демонстрационный режим использует исключительно синтетических пользователей. Уведомление описывает реализованную обработку, не заявляет юридическую сертификацию.
