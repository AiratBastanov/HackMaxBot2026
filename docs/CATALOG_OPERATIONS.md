# Обслуживание каталога

Обычный запуск — [README](../README.md). `catalog-init` готовит данные до старта polling или webhook и не обращается к MAX, не загружает токен и не открывает SQLite.

## Выбор версии и свежесть

При запуске проверяются schema, ссылки на файлы, canonical hashes снимков, review, действующая source policy и 72-часовой срок каждого наблюдения. Свежий комплект устанавливается атомарно. Более поздний операторский каталог сохраняется целиком, включая отсутствие источников. Иначе сравниваются наблюдения каждого источника: более новые факты сохраняются, независимые источники из нового комплекта добавляются. Старые городские shards разделяются по источникам с наследованием исходных наблюдений и сроков review. При равных версиях файлы и указатель не переписываются.

Версионные файлы записываются и проверяются до атомарной смены указателя. Ошибка чтения, проверки или установки сохраняет прежний пригодный каталог. SQLite, закладки, cursor, предпочтения и состояние доступа независимы от этой операции. Закладки открывают безопасно сопоставленные текущие сведения по прежним правилам; изменённые условия показываются пользователю.

Свежесть наблюдений, срок пересмотра политики использования источника и даты событий — разные ограничения. Для защитного снимка наблюдения истекают 29.09–01.10.2026; source policy требует пересмотра 26.10; окно событий до 26.11 не продлевает первые два срока.

## Короткое обновление перед стартом

Если ни runtime, ни комплект не дают пригодных событий, init использует существующие адаптеры датированных афиш Башоперы, Самарской оперы и Санктъ-Петербургъ Оперы — подмножество утверждённого реестра 26 источников. Он обращается только к известным входным страницам и их условиям/площадкам, соблюдает HTTPS, robots, интервалы, ограничения ответов и проверку публичных адресов. Новые сайты не открываются. Предел — **120 секунд сетевой работы и 24 запроса**; остановка после первого пригодного проверенного источника. Кеш младше 72 часов переиспользуется без изменения fetchedAt; общий журнал и бюджеты кампании сохраняются.

Такой bootstrap даёт доступную свежую часть афиши, а не обещает немедленное восстановление всех 858 событий. Независимые прежние shards сохраняются со своими исходными сроками; просроченные не показываются. При отсутствии пригодных данных выводится одна подсказка о проверке доступа и повторе команды, приложение не начинает получать MAX updates. После истечения source policy нужен рассмотренный выпуск с действующими основаниями использования источников; даты review автоматически не продлеваются.

## Диагностика и полное обновление

Сохраните тот же Compose project, том, identity, секреты, CA и timeout. Остановите приложение в согласованное окно. Диагностика той же операции без запуска потребителя:

```powershell
docker compose --env-file .env.public -f compose.polling.yaml run --rm catalog-init
```

Вне Compose, после сборки TypeScript, тот же доменный шаг: `node dist/scripts/catalog-prepare.js`. Пути по умолчанию: `catalog/real`, `runtime/catalog`, `runtime/source-cache/bootstrap`. Одновременно подготовкой управляет один процесс. Synthetic demo пропускает этот шаг и обращения к источникам.

Для полного операторского обновления используется существующая команда; `city:spb` можно заменить ID источника или убрать для всего реестра:

```powershell
docker compose --env-file .env.public -f compose.polling.yaml run --rm --no-deps app node dist/scripts/real-catalog.js multi-refresh runtime/source-cache/refresh-01 city:spb
```

Продолжение одной кампании использует тот же путь и счётчики. `multi-collect` готовит кандидат; `multi-reparse` разбирает кеш; `multi-recover` проверяет прерванного владельца перед продолжением. Для новой независимой съёмки задаётся новый каталог. Лимиты полной кампании: 4 000 запросов, 1 000 MB, 90 минут сетевой работы; волна до 30 минут. [Подробная процедура и исходное измерение](verification/MULTI_CITY_CATALOG.md#воспроизведение-и-продолжение). Неполученная страница не означает отмену события. Расписание полного обслуживания задаёт оператор.

При ошибке проверьте доступ контейнера к HTTPS-сайтам и логи `docker compose --env-file .env.public -f compose.polling.yaml logs catalog-init`. После прерванной кампании сначала используйте `multi-recover runtime/source-cache/bootstrap`; файлы фактов и тома удалять не нужно. Для конфликта версионных файлов сохраните их для диагностики и восстановите из проверенного комплекта/резервной копии, не редактируя даты и hashes вручную.

## Контролируемое обновление установленного бота

В согласованное оператором окно, из той же настроенной копии:

```powershell
docker compose --env-file .env.public -f compose.polling.yaml stop
git pull --ff-only
docker compose --env-file .env.public -f compose.polling.yaml up --build
```

Подготовка каталога выполняется автоматически. Ручная смена указателя и удаление тома не требуются. Для постоянного размещения оператор настраивает HTTPS webhook, долговременный диск, резервирование и период обслуживания по [инструкции](ORGANIZER_CHECK.md#постоянный-webhook).
