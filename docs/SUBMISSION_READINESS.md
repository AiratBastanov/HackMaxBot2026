## Контролируемая установка и постоянная оценка

Это оставшийся операционный шаг, **не выполненный в задаче защиты**. Оператор в согласованное окно сохраняет тот же Compose project/том, identity, секреты, CA и timeout. Комплект в образе копируется в `/app/runtime/catalog/active.json` только при отсутствии указателя. `git pull`, rebuild и restart сами по себе существующий runtime-каталог не заменяют; том удалять не требуется.

Используется [проверенная процедура install-bundled / multi-refresh](verification/MULTI_CITY_CATALOG.md#воспроизведение-и-продолжение): для ещё свежего комплекта — `install-bundled` с SHA-256 точных байтов снимка; после expiry — новая ограниченная операторская `multi-refresh` с проверками и атомарной установкой. Для продолжения той же кампании сохраняются её путь и счётчики. Каталог из репозитория не выдаётся за уже установленный в бот.

Свежесть фактов — 72 часа: часть удержанных наблюдений истекает 29.09, новые 01.10. Пересмотр source policy 26.10 и окно событий до 26.11 — независимые сроки. Чтение, сборка презентации, кеш и установка свежесть не продлевают.

Для постоянно доступной оценки нужны отдельно согласованные оператор/контакт, инфраструктура с постоянным диском и резервированием, DNS/HTTPS, период доступности и ответственность за refresh. Профиль webhook подготовлен; переключение и регистрация подписки — отдельная операционная работа. Применимые значения заносятся только в [закрытый шаблон](PRIVATE_HANDOFF_TEMPLATE.md); адресаты и канал остаются незаданными. Остаток human/MAX проверок отложен пользователем и не запрашивается в этой задаче.
