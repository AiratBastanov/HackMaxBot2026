## Семантика запроса и данных

Новый Query `version:2`: canonical city, timezone, party `{adults, childAges}`, `budgetBasis:PARTY_TOTAL`. Основа бюджета сохраняется и в draft. Вопрос — **«Бюджет на вход для всех»**. Изменение количества/возрастов очищает прежний бюджет и результаты; требуется задать сумму заново. City/party/filter edit сбрасывает candidate opt-in и действия. Закладки других городов сохраняются.

Реестр: Казань (`kzn`, UTC+3), Екатеринбург (`ekb`, UTC+5), Москва (`msk`), Санкт-Петербург (`spb`), Нижний Новгород (`nnv`), Новосибирск (`nsk`, UTC+7). Членство не означает доступную афишу. Кнопки строятся по имеющимся snapshots, а не по всему реестру. Неоднозначное сокращение предлагает уточнение; неизвестное имя не превращается в provider ID/URL. Получение `/locations` в этой работе не потребовалось: использованы документированные slugs/timezones и прежняя Казань. Новых provider-запросов/загрузок событий — **0**.

В новом `compactFixture` — только **две вымышленные локальные подборки: Казань и Екатеринбург**, по четыре события. Существующий реальный исследовательский материал остаётся только казанским, историческим и EXPLORATORY_ONLY. Москва и остальные города без снимка дают recoverable сообщение. Catalog принимает один прежний snapshot либо bundle `{snapshots:[...]}`; режимы не смешиваются, повтор одного city отвергается. CLI `fetch --city ekb` принимает только registry ID и использует namespace `<cache>/ekb`; смена города в resume/записи прежнего snapshot запрещена. Эта возможность проверена fake JSON client без скачивания каталогов. Старые команды Казани и кеши сохранены.

Сегодня/завтра, окно запроса, часы входа и отображение вычисляются в timezone выбранного города. Прямой city text действует только в активном состоянии города; known duplicate delivery и старый timestamp/reply target отвергаются. Неизвестный произвольный текст не сохраняется как название: в inbox остаётся нейтральный отказ. Нельзя идеально связать намерение с запоздалым текстом без reply или с прошлой редакцией того же mid; такой гарантии нет. Draft виден в сводке и обратим.

Единый evaluator суммирует только применимые взрослые/детские тарифы. Вымышленный пример: 2×200 + 1×100 = **500 ₽ за всех**. При неизвестной детской цене: **итого неизвестно, известная часть 400 ₽**. Доказанная нижняя граница выше бюджета исключает событие, ниже — не доказывает доступность. FROM, conditional, group/package остаются явными; пересекающиеся/неприменимые тарифы консервативно неизвестны. Оптимизация пакетов не реализована. Для прежней неопределённой FROM сохраняется только доказанная общая нижняя граница; явно per-adult FROM суммируется с другими известными компонентами.

Provider age label хранится отдельно от явного minimumAge/допуска детей и тарифных возрастных диапазонов. Никакое общее юридическое правило из маркировки не выводится. Известный запрет/несовместимый возраст исключает, неизвестный допуск остаётся candidate. Нормализатор KudaGo сохраняет `age_restriction`, когда поле получено; детские тарифы/семейные пакеты из текста автоматически не изобретаются. Соответствие цены не подтверждает билеты или регистрацию.

## Доставка, сбои и сохранность

SQLite **v3** добавляет только `flow_screens` и `ui_messages`: actor/chat, подтверждённый mid, purpose, epoch/revision, статус и hash отправленной редакции. Callback содержит случайный action token, не адрес изменения. Worker последовательно обрабатывает UI; устаревший pending view отбрасывается. Контроль actor/revision/catalog и provider display применяется до отправки, LiveMax имеет независимый guard. Bot-origin updates игнорируются.

PUT заменяет текст и весь массив attachments; `[]` снимает клавиатуру. POST /answers используется только для notification, без второй копии обновлённого сообщения. `notify:false`, общий интервал 1100 мс; method-specific ответы проверяются, включая HTTP 200 / `success:false`. Подтверждённое создание — единственное основание принять новый mid. Поздний результат не откатывает draft или desired revision.

Неоднозначный PUT не повторяется вслепую: выполняется один GET с проверкой bot/actor/chat/mid и сравнением текста/клавиатуры. Совпавшая редакция разрешает дальнейшую работу; несовпадение/ошибка изолирует прежний mid и допускает одно новое создание текущей редакции. После crash MUTATING переходит в UNCERTAIN. Это reconciliation, **не обещание атомарной замены на серверах MAX**.

После подтверждённого нового экрана удаляется только конкретный tracked obsolete UI. Отказ DELETE допускает одну попытку снять его клавиатуру; неудача не зацикливает выбор, старые действия отвергаются сервером. Неопределённый результат cleanup не вызывает конфликтующую слепую запись. User messages, старый chat history, probe/диагностика и чужие сообщения не очищаются. Права администратора не предполагаются: **реальная допустимость DELETE в private MAX ещё не проверена**. Прежние stop rules сохранены для основного edit пути; отдельная уборка не отменяет успешный выбор, AUTH останавливает campaign.

Миграция прежнего draft детерминирована: исторически один взрослый/Казань, эквивалентная сумма на одного становится суммой на всех в новом draft. Старые bookmark JSON, query, generation, price basis и provenance **не переписываются**. Старые неполные Card отображают отсутствующий контекст; текущие факты не дорисовываются. Recovery принимает schema 2/3 и очищает новые ссылки на UI в quarantine/discard. Erasure очищает возраст/состав, старые personal inbox/outbox payload и UI references; текущий нейтральный ACK сохранён. История MAX и прежние backups не объявляются стёртыми.
