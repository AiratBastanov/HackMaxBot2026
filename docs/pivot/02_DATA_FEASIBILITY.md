## Минимальный договор о фактах для следующего этапа

Нужны источник/URL/разрешённый способ использования, локальный стабильный ID и версия; вид `TIMED_SESSION` или `FLEXIBLE_VISIT`; опубликованное расписание, часовой пояс, признак вычисленного end; вид цены и применимость; место/зона; возраст и инструкция записи; `source_published_at`, `source_modified_at`, `last_successful_check_at`, режим доказательств. Для каждого существенного поля — источник, а не единый нерасшифрованный score. Это описание требований к данным, **не новая схема БД и не выполненная миграция**.

Предлагаемый предел актуальности для подбора — успешная редакционная сверка не старше 24 часов, повтор перед демонстрацией; это операционная цель, не свойство сайтов. При неполном обновлении сохраняется прежняя версия с отметкой устаревания и исключением из строгой актуальной выдачи. Сравнивать можно только успешно полученные версии одной сущности: дату, время, цену, адрес, правила. Пропажа в списке/timeout/404 не доказывает отмену. Без надёжного occurrence ID нельзя автоматически перенести пользовательское напоминание на другой сеанс.

**Решение о данных:** для следующей разрешённой реализации предлагать малый `PREPARED_REAL_DATA` набор с видимой маркировкой и владельцем сверки; допуск рабочего импорта требует закрыть права, устойчивость и полноту. Партнёрский PRO API, автоматический каталог всего города и мониторинг отмен не являются предпосылками подготовки диалога, но не могут быть заявлены реализованными. Сначала подтвердить эту границу с пользователем, затем выполнить этап 1 [плана](03_IMPLEMENTATION_PLAN.md).
