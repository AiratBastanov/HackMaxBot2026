## A. Владельцу данных

**Кому:** `opendata@mincultrf.ru`

**Тема:** Ограниченный доступ к актуальным событиям Казани для некоммерческого MAX-бота

Здравствуйте! Готовим для хакатона MAX-бот «Культурный план»: подбор опубликованного события по времени и бюджету, объяснение условий и личная закладка. Запись/покупка остаются на сайте поставщика. Подскажите рекомендуемый разрешённый канал данных Казани: ключ документированного API открытого набора `7705851331-events`, небольшой актуальный JSON/XML-экспорт либо ограниченный PRO-доступ.

Паспорт показывает версию 13, но форматы её скачивания отсутствуют; API без ключа даёт 401, архив версии 12 — около 10 GB. Для проверки нужны 20–30 разных событий на следующие 30 дней. Затем предполагаем до 100 записей за цикл, обновление раз в сутки и локальный кеш версий до 7 дней. Нужны ID/название, город/место, период и сеансы с часовым поясом, цена/бесплатность и условия тарифа, возраст, внешняя ссылка записи/события, время изменения и сведения об отмене при наличии. Фото, полные редакционные тексты и персональные контакты не запрашиваем.

Указываем Минкультуры/PRO и ссылки на источники. В GitHub хотим размещать лишь небольшие нормализованные примеры с атрибуцией; для открытого набора следуем опубликованным условиям. Для предложенного альтернативного канала просим уточнить допустимость такого примера, кеширования и обновления. Если подходящей выгрузки/API нет, возможно ли письменное разрешение на ограниченный сбор перечисленных полей с портала? Без него scraper не создаём. Укажите, пожалуйста, пример разрешённого запроса Казани и порядок получения доступа.

## B. Организаторам

**Получатель:** подтверждённый канал технических вопросов хакатона — установить перед отправкой.

**Тема:** Уточнение R14 для официального открытого набора и партнёрского API PRO

Здравствуйте! Для бота подбора культурного события в Казани рассматриваем официальный набор Минкультуры [`7705851331-events`](https://opendata.mkrf.ru/opendata/7705851331-events). Его [условия](https://opendata.mkrf.ru/item/license) разрешают свободное повторное использование и распространение с источником. [Документированный read-only API](https://opendata.mkrf.ru/item/api) требует бесплатно выдаваемый `X-API-KEY`; публичный ZIP скачивается без ключа, но велик для пилота.

Правильно ли мы понимаем, что такой документированный доступ к открыто лицензированному набору совместим с запретом «частных API» на стр. 7? Если поставщик вместо него предложит официальный партнёрский PRO API с ключом по соглашению и разрешением на использование фактов, будет ли он допустим и какие условия распространения нужно показать? [PDF PRO](https://pro.culture.ru/documentation/export_API_PRO.pdf) содержит Pushkin Card-метод; универсальный поток мы пока не заявляем проверенным.

Используем только фактические поля, не размещаем ключи/полные ответы/медиа в репозитории; источник, свежесть и подготовленный режим показываем явно. На стр. 8/18 открытые наборы и сайты организаций описаны как возможные источники. Просим оценить именно эти каналы, а не наличие ключа само по себе.
