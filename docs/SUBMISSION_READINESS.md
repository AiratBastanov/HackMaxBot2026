## Продукт и реализованный путь

«Культурный план» помогает взрослому жителю Казани выбрать одно культурное занятие по дате, времени и бюджету на вход. Пользователь задаёт условия, при желании выбирает интерес, смотрит до трёх совпадений по известным данным. Отдельная кнопка открывает до трёх вариантов с неизвестными условиями. Интерес влияет на порядок, обязательные ограничения не расширяются. Карточка показывает место, часы или сеанс, последний вход, применимую цену, регистрацию и источник. Событие можно сохранить, открыть и удалить из личного списка; `/delete_data` очищает закладки и параметры. Сохранение не означает регистрацию или покупку билета.

Сценарий реализован в существующем боте: HTTP → durable inbox → worker → SQLite → renderer → транспорт MAX. Локальные примеры полностью вымышлены. Актуальная доступность реальных событий, востребованность и выигрыш во времени не доказаны. [Продуктовое решение](pivot/01_PRODUCT_DECISION.md) и [пять этапов](pivot/03_IMPLEMENTATION_PLAN.md) остаются действующими документами.

## Короткая демонстрация

1. Объявить: технический тест на вымышленных событиях; данные провайдера пользователям не отправляются. Записать code/image и версии клиентов. Для локальной демонстрации: `node dist/scripts/readiness-walkthrough.js`; вывод создаётся renderer, MAX симулирован.
2. `/start` → Подобрать → Другая дата → Назад → Завтра → время → бюджет 500 ₽ → Театр. Показать две категории, театр первым и отдельную группу совпадений.
3. Открыть детали: адрес, 10–18, последний вход 17:30, взрослый билет 200 ₽, обязательная регистрация. «Все условия» раскрывает отдельные сведения/наблюдения. Изменить фильтр и показать сброс opt-in.
4. Явно включить кандидатов: мастерская остаётся вариантом с неизвестным взрослым тарифом, при известном пересечении 12–18. Кнопки внешних ссылок помечены как примеры; доступность страницы не обещается.
5. Сохранить → список → другой клиент того же аккаунта → открыть → удалить → сохранить снова → restart test app → открыть → `/delete_data`. Второй согласившийся аккаунт отдельно проверяет изоляцию. Только фактические действия MAX считаются наблюдениями.

Для реального сеанса действуют [F01–F10 и маршруты runbook](EXPLORATORY_MAX_RUNBOOK.md), по умолчанию 15 минут, явно запрошенное новое окно — до 30 минут; в обоих случаях ≤120 polling requests. Записать ограничения недоступных действий; нельзя подставлять локальный PASS вместо клиента.
