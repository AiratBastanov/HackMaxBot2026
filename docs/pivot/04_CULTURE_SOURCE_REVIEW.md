### Что именно устанавливают правила

В PDF организатора повторно прочитаны страницы **7, 8, 18**, SHA-256 `638e5de074ea38645f367d2c9d00385064a6db4c8e29036d1efc450a04c0914a`. Страница 7 запрещает закрытые библиотеки, частные API и чужой код без разрешения на свободное распространение/использование, требует соблюдения правил и маркировки подготовленных данных. Страницы 8/18 предлагают официальные источники, открытые данные и сайты организаций, требуют проверять период/территорию/актуальность. **Явного общего запрета parsing публичных страниц нет.** Требования и веса в 00 не менялись.

Пункт 5.4.4 правил Culture.ru запрещает: «Использовать без соответствующего письменного разрешения Администрации автоматизированные программы для сбора информации на Портале и/или взаимодействия с Порталом и его сервисами». В разделах 1/2 правила связывают понятие пользователя и акцепт с регистрацией; это не судебное определение законности каждого анонимного GET. Для нашего проекта документированное условие достаточно, чтобы не создавать сборщик каталога без разрешения. Указание источника в футере не заменяет это разрешение. Условия PRO и лицензия Минкультуры рассматриваются отдельно. Robots.txt не использовался как лицензия или способ авторизации.

Собственная страница лицензии Минкультуры прямо разрешает приложения и некоммерческое/коммерческое повторное использование без договора, с сохранением источника и без искажения. Паспорт ссылается на типовые условия `data.gov.ru/information-usage`; этот адрес вернул HTTP 200 и 671-byte JS-оболочку, а не текст условий. Вывод о допустимом повторном использовании основан на **полученной странице самого Минкультуры**, не на предположении о содержимом оболочки. Нормализованные факты/агрегаты можно публиковать с атрибуцией; фотографии и редакционные тексты для задачи не нужны и не копируются.

## Машинная проба и её ограничение

Перед загрузкой записан локальный sampling plan. Directory показал **643 числовых JSON-member**, без региональных имён; минимальный `643.json` занимает **10 651 437 compressed / 63 325 150 expanded bytes**, весь архив — **62 004 996 206 expanded bytes**. Поэтому даже минимальный member целиком не брали. После этого план уточнён для одной диагностической пробы: первые 4 MiB именно этого member, до 32 MiB распаковки и 10 000 закрытых JSON-объектов. Другие shard ради достижения числа 20–30 не обходились.

Это **позиционная архивная выборка**, смещённая по способу выбора. Нет основания считать последний номер самым новым или репрезентативным. Распаковано **24 933 299 bytes**, завершённых JSON-объектов **2 671**, неполный хвост исключён, CRC всего member **не проверен**. Они не пополняют целевую казанскую выборку.

## Стратегия после этой проверки

1. **Приоритет — официальный открытый набор**, с небольшим ответом документированного API или экспортом владельца. Для расширенного API необходим легитимно выданный ключ; наличие ключа ещё не доказывает работу нужных фильтров. Получить 20–30 разных актуальных событий Казани и проверить поля/сеансы/ссылки до обещания каталога. Полный архив на 10 GB не включать в базовую эксплуатацию.
2. Стабильный event key — namespace набора + `general.id`; venue — отдельный ID. Если отдельного session ID нет, сочетание event/place/start/end лишь технический идентификатор наблюдения. Смена времени требует сопоставления, не автоматического переноса напоминания. События с несколькими площадками нельзя декартово перемножить на общий список seances без проверенной связи.
3. Предложение по эксплуатации: ограниченный запрос Казани на 30 дней **раз в сутки**, локальный кеш фактов/версий до 7 дней, повтор перед демонстрацией. Паспорт заявляет недельное обновление; суточная проверка не делает первоисточник ежедневным. `source_update`, версия выгрузки, HTTP Last-Modified и `last_successful_check_at` показываются раздельно. После 24 ч без успешной сверки не выдавать старое как актуально проверенное.
4. При 401/403 остановить обновление и показать проблему доступа оператору; при timeout оставить предыдущую версию с отметкой устаревания. Пустой ответ, пропажа/404 и изменение версии не равны отмене. Отмена — только явное подтверждение с документированной семантикой. Статусы из архивного wrapper не использовать для уведомлений по догадке.
5. Публикация: источник «Открытые данные Минкультуры России, данные PRO.Культура.РФ», ссылка на паспорт и, если реально предоставлена, карточку события; дата/тип преобразования. В Git — только минимальные факты/агрегаты и синтетические fixtures. Фото, полный HTML/description, персональные контакты, cookies и ключи не нужны.
