## Причины и граница доказательства HTTP 400

В исходном коде сводка знала только `exhibition`/`theater`: концерт, занятие и экскурсия попадали в подпись «любая», хотя canonical preference сохранялся и использовался при ранжировании. Сохранение по новой кнопке намеренно создавало ещё один UUID без проверки равного посещения. Список не выводил цену, а обычные действия включали полное стирание. Это причины воспроизведённых расхождений продукта.

На исходном HEAD отдельно воспроизведено: синтетический отказ редактирования HTTP 400 создавал **один заменяющий POST**, после исправления — **ноль**; контакт в обоих случаях оставался доступен. Изначальный код не приравнивал всякий HTTP 400 к Stop. После полного стирания отсутствие контакта было штатным, но восстановление обычным свежим личным сообщением для ряда состояний не было разрешено. Старый финальный ответ строил пустой `inline_keyboard`; теперь отправляется обычное сообщение без клавиатуры. Связь этой формы с историческим отказом MAX не доказана.

Историческое тело ответа/точный payload отсутствуют: **причина исходного HTTP 400 — NOT_ESTABLISHED**. Потеря адресата, устаревший mid, неверная клавиатура или реальное прекращение общения не объявлены установленными. Новый журнал ограничен методом, категорией, разрешённым `chat.denied`, размерами/типами и `outbox-N`; для разбора тела ошибки установлен предел 4 КиБ, тело не журналируется. Нет текстов, user/chat ID и токенов.

По [общему контракту MAX](https://dev.max.ru/docs-api) HTTP 400 — неверный запрос. Только `403/chat.denied` обычного private [POST /messages](https://dev.max.ru/docs-api/methods/POST/messages) без пересылки переводит контакт в восстановимый отказ доставки; это не lifecycle Stop. События прекращения и возобновления различаются по [Update](https://dev.max.ru/docs-api/objects/Update). Ошибки payload, auth, rate limit и неоднозначная сеть остаются отдельными. Одинаковый неверный POST не повторяется; прежние ограниченные retries для 429 и reconciliation неоднозначного результата сохранены.

Удаление одной строки → commit → ответ проверены с отказом отправки: строка исчезла, остальные параметры/закладки сохранились. Полное стирание фиксируется до сети; краткий финальный outbox очищается независимо от доставки и не может стереть новый диалог. POST проверяет возвращённый Message; [PUT /messages](https://dev.max.ru/docs-api/methods/PUT/messages) и [POST /answers](https://dev.max.ru/docs-api/methods/POST/answers) — `success:true`, а не один HTTP 200. Payload — plain text до 4000, клавиатура до 30 рядов/7 кнопок (3 для ссылок), ссылки до 2048; приложение сохраняет более строгие пределы подписей/callback. [Ограничения клавиатуры](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard).
