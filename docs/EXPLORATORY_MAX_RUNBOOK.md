# Культурный план: реальный технический smoke mobile/web

**REAL_APPLICATION_SMOKE = REQUIRED. Mobile = NOT_VERIFIED; web = NOT_VERIFIED.** Локальные HTTP/Docker результаты в [08](pivot/08_EXPLORATORY_BOT_RECEIPT.md) не являются человеческим наблюдением MAX. В этой задаче реальных отправок и изменений подписок не было.

Этот runbook применим к уже согласованным проектному боту, существующему endpoint, оператору и двум согласившимся тестировщикам. Их наличие не подтверждено. Нельзя ради прогона создавать hosting, менять subscriptions, открывать desktop наружу или использовать другой бот. Рабочие секреты — только через закрытое окружение/secret files, никогда в чат. При отсутствии предпосылок остановить live-часть; локальный `npm run flow:demo` остаётся доступен.

## Подготовка на уже разрешённом окружении

1. Зафиксировать SHA исходников/образа, действующий bot ID и endpoint без секретных параметров. Убедиться, что consumer один и `/healthz` отвечает. Не изменять подписки этим runbook. Предыдущий G1 не доказывает текущую доступность.
2. Сохранить существующую БД; для технического smoke выделить отдельную согласованную live test SQLite, не переносить local DB. Нужны `APP_MODE=live`, прежние закрытые MAX настройки и `PROBE_TESTER_IDS` только двух тестировщиков. `LIVE_SCOPE_CONFIRMED` отражает реальное разрешение, не создаёт его.
3. Сгенерировать **новый полностью вымышленный** каталог на фактические часы: `node dist/scripts/prepare-flow-fixture.js --synthetic-current /app/runtime/synthetic-client-test.json`. Существующий файл команда не заменяет. Выбрать `FLOW_DATA_MODE=synthetic-test`, `DATA_SNAPSHOT_PATH=/app/runtime/synthetic-client-test.json`. **Не задавать FLOW_TEST_CLOCK для реальных клиентов:** timestamps входящих MAX событий действительные. Такой каталог имеет отдельный synthetic mode, явные названия и ссылки example.org; это не передатирование реальных событий.
4. Применить конфигурацию только на уже разрешённом test endpoint; не развёртывать новую инфраструктуру в рамках этого задания. Проверить стартовый `dataMode=synthetic-test`. Данные провайдера в MAX не передаются: `PUBLIC_DISPLAY=NOT_CLEARED` остаётся закрытым кодом.

## Сеанс: до 15 минут на клиент

Выполнить таблицу отдельно в mobile и web. Записать версию/платформу клиента, время, actual и минимальное обезличенное evidence; таблица ниже не помечается PASS заранее.

| Проверка | Действие и ожидаемое наблюдение | Mobile | Web |
|---|---|---|---|
| F01 | `/start`: видна маркировка технического теста, «Подобрать», «Мои события», «О данных» | NOT_VERIFIED | NOT_VERIFIED |
| F02 | Подобрать → Завтра → 12–18 → до 500 → Любой. Видны условия; нажать результаты. Только «выставка света» как strict | NOT_VERIFIED | NOT_VERIFIED |
| F03 | Отдельно нажать «Показать варианты для проверки»: «мастерская цвета», цена от 300, взрослый тариф неизвестен. «Дорогой зал» отсутствует | NOT_VERIFIED | NOT_VERIFIED |
| F04 | Подробнее 2 → точная source link-кнопка. Открывается example.org; нет автоматического preview. Затем сохранить — это явно не регистрация | NOT_VERIFIED | NOT_VERIFIED |
| F05 | Мои события → открыть. Неопределённость остаётся. Перейти во второй клиент того же пользователя: список сохраняется | NOT_VERIFIED | NOT_VERIFIED |
| F06 | Изменить бюджет на 0: прежний opt-in сброшен. Нажать старую кнопку, затем использовать актуальную; нет смены события/отката фильтра | NOT_VERIFIED | NOT_VERIFIED |
| F07 | Другая дата: ошибочная `КОД 2030-04-31` даёт исправление; актуальная дата с кодом формы принимается. Обычные кнопки не требуют «готово» | NOT_VERIFIED | NOT_VERIFIED |
| F08 | Удалить закладку, сохранить её снова. Старое подтверждение удаления не удаляет новую. `/delete_data` → подтверждение очищает личный список | NOT_VERIFIED | NOT_VERIFIED |
| F09 | B открывает свой список — данных A нет. Если клиент не позволяет переслать callback, зафиксировать ограничение; не подменять human evidence локальным wrong-actor тестом | NOT_VERIFIED | NOT_VERIFIED |
| F10 | `/probe` запускает отдельный G1; `/start` возвращает главный продуктовый экран. Stop/mute не создают рассылку/напоминания | NOT_VERIFIED | NOT_VERIFIED |

Если сообщение не приходит, проверить обезличенный статус outbox: SUPPRESSED_DISPLAY, контакт, STALE, FAILED_SEMANTIC, UNKNOWN_RESULT. HTTP 200 и ACKNOWLEDGED не доказывают видимость человеку. Не повторять неоднозначную отправку автоматически; новый `/start` — отдельное действие пользователя. После сеанса остановить только согласованный test процесс и сохранить результаты без credentials/raw payloads.

Даже два реальных smoke PASS не открывают публичный показ KudaGo, не подтверждают спрос и устойчивость строгой афиши. Напоминания и deployment остаются отдельным объёмом.
