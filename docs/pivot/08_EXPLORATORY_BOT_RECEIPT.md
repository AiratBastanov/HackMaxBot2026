## Что соединено в приложении

Главная («Подобрать», «Мои события», «О данных») → дата/время Москвы → бюджет взрослого → необязательный интерес → подтверждение условий → до трёх strict → отдельное «Показать варианты для проверки» → детали/точная source link → сохранить → личный список/детали → удалить. Есть редактирование одного фильтра, явный custom-формат с кодом формы, восстановление для пустого, неполного, старого, отсутствующего или неподходящего по области снимка, неверного ввода и истёкшей кнопки.

`src/culture/flow.ts` использует существующий `select`, без второго фильтра. UNKNOWN не становится MATCH, MISMATCH не попадает к кандидатам. Opt-in относится только к текущему запросу; изменение фильтра или новый вход его сбрасывает. Карточки говорят «Соответствует указанным данным источника» или «Нужно уточнить условия», раскрывают применимые неизвестные факты, конкретное время/цену и действие проверки. Цена «от» остаётся нижней границей. Нет заполнения трёх позиций дубликатами.

Сохранены один Fastify, authenticated webhook, lossless actor IDs, один worker, durable inbox/outbox и одна SQLite. Обычный старт ведёт в продукт, `/probe`/payload `g1` — в прежнюю диагностику. На code review воспроизведён сброс нового экрана запоздалым `/probe` (одна целевая регрессия сначала FAIL). Переключение владельца диалога теперь происходит после принятия входа, сохраняет монотонную ревизию и timestamp; финальная регрессия проверяет оба направления, без удаления существующих safety assertions.

## Контракты MAX и устаревшие действия

24.09 прочитаны официальные [клавиатуры](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard), [POST messages](https://dev.max.ru/docs-api/methods/POST/messages), [POST answers](https://dev.max.ru/docs-api/methods/POST/answers), [Update](https://dev.max.ru/docs-api/objects/Update). Добавлен `{type:link,text,url}`; URL до 2048 символов, текст сообщения до 4000, клавиатура до 30 рядов/7 кнопок (3 для ряда со ссылкой). Рабочие экраны существенно меньше пределов. `disable_link_preview=true` передаётся как query-параметр, не как вымышленное поле body. Сохранены `notify:false`, методные проверки ответов и отдельный FAILED_SEMANTIC для HTTP 200 / success:false. Pacing worker — одна операция через ≥1,1 с в runtime, строже лимита двух сообщений/ответов в секунду.

Короткая случайная ссылка действия хранится сервером вместе с actor, purpose, revision, аргументом и TTL 15 минут. Payload не содержит user ID. Повтор доставки дедуплицируется, чужие/старые действия не меняют состояние. Custom-ввод привязан кодом к текущей форме; произвольные сообщения не архивируются. Выбор и renderer синхронны в короткой транзакции; сетевой вызов — после commit. Pending-экраны проверяются по revision и hash снимка, включая новые уже принятые inbox события. Результат уже начавшегося transport send не перепривязывается к новой ревизии, помечается `SENT_BEFORE_NEW_INPUT_OR_SNAPSHOT`; отозвать уже переданный HTTP запрос этот прототип не обещает. Старые кнопки всё равно недействительны. Неоднозначные отправки автоматически не повторяются.

`Catalog` — одна явная граница: ограниченный файл, schema validation, immutable snapshot, hash содержимого и реестра review. Чтение только на startup; после контролируемого refresh CLI — restart. В webhook/SQLite-транзакции нет загрузки файла или KudaGo. Частичность, scope, version, конфликты и timestamps исходных наблюдений не обновляются чтением. Неверный/отсутствующий файл даёт недоступность, без синтетической замены. Смешение real/synthetic отклоняется; live real запрещает внедрение test clock.

## Закладки и хранение

SQLite `user_version=2`: миграция добавляет flow states/actions, bookmarks и fences outbox; fresh/v1/repeated startup проверены на временных БД. Живая БД не использовалась как fixture и не сбрасывалась. Сохранены WAL/FULL, mode/bot identity и восстановление SENDING как UNKNOWN_RESULT.

Закладка содержит namespaced event/occurrence, hash стабильной пары, случайное generation, минимальный текстовый контекст, ссылку/источник, неопределённость, query, version/fingerprint и дату исходных данных. Сохранение идемпотентно; до 50 записей, по пять на страницу. Generation плюс revision защищают delete → save again → delayed old delete. Для flexible visit намерение пользователя хранится как query, а `occurrence.start` остаётся null. Исчезновение записи не объявляется отменой, изменение не переносит закладку на другой сеанс; показывается прежняя ссылка с ограничением. Карантин остаётся видимым ограничением, не обычным uncertain match.

Локальная политика: действия — 15 минут, состояние — 30 дней без активности, закладки — до удаления; `/delete_data` требует явного подтверждения и очищает закладки/параметры и прежние payload данного диалога. Probe cleanup не удаляет активные продуктовые записи. Inbox/outbox технические tombstones — 7 дней, payload завершённых очередей — сутки. Имена, телефоны, координаты пользователя, произвольные архивы сообщений не собираются. Публичная политика оператора/backup recovery ещё не подтверждены. Напоминания и рассылки отсутствуют.

## Показ, публикация и оставшиеся границы

**PUBLIC_DISPLAY = NOT_CLEARED.** По [KudaGo API conditions](https://docs.kudago.com/api/) сохраняются точные ссылки/атрибуция; требование индексируемости не означает фактическую индексацию, MAX link button не объявлен исполнением всех условий. Это не blanket legal ban и не вымышленная необходимость ключа. Worker и LiveMax блокируют provider payload даже при ошибке/старой очереди; renderer даёт нейтральное объяснение. Сторонние фото, полные описания, каталоги и рекламные материалы не публикуются; новый сайт/mini-app не создавался.

Действующие бот/endpoint/consenting testers не подтверждены имеющимися evidence. Поэтому real MAX действий, subscriptions и deployment нет. [Mobile/web runbook](../EXPLORATORY_MAX_RUNBOOK.md) подготовлен, фактических human PASS нет. Данные пригодны только для принятого exploratory scope; спрос, устойчивое строгое обещание и публичный выпуск не сертифицированы.

Для review подготовлен `.review/exploratory-source-review.zip`: явный allowlist source/tests/scripts/config, безопасные примеры, релевантные docs и synthetic evidence. Environment files (включая шаблоны), secrets, DB, raw provider/MAX, dependencies/dist/tools/private исключены. Список entries, SHA-256 и проверка распаковки/целостности — `.review/exploratory/archive-manifest.json`; ZIP никуда не загружался.

Git-публикация — обычный reviewed commit/push только явного task-owned allowlist. Проверяются реальные remote URL, upstream и SHA; force/rebase/reset/stash не используются. Точная квитанция commit/remote/remaining changes после push — ignored `.review/exploratory/git-publication.json` и финальный ответ. Собственный будущий commit hash в этот документ не подставляется.

Методика использует ранее прочитанные официальные [M‑01](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide), [M‑02](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra), [M‑03](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra): контекстные чтения, завершение разрешённого объёма и проверки по риску изменений. Deferred research не возобновлялась.

Следующая внешняя граница — подтверждённая инфраструктура/тестировщики для двух клиентов и отдельное решение об условиях публичного показа. Пять этапов сохранены; после локального flow/закладок работа останавливается, напоминания/дальнейший импорт/публичный deployment не начинаются.
